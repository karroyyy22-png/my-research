## 目的
把 ASAP 现有的两类输出（二分类头 `p_fake`、四个多标签头 `p_FS,p_FA,p_TS,p_TA`）解码成九类/六类标签，回答三个问题：
1. 不同解码规则（以二分类为先 vs 四头联合打分 vs 校准/学习的组合）在六分类上差多少？差距是否只是 Original 工作点挪动造成的？（E01）
2. 六分类/九分类的错误主要落在哪一层：真伪、模态、子类型？（E02）
3. 二分类头与四个多标签头之间有多少冲突？冲突样本是否更容易错？四个头的校准情况如何？（E03）

每条结论只写成 **支持 / 不支持 / 证据不足**。

### 标签
- 九类 = 图像状态{无,FS,FA} × 文本状态{无,TS,TA}；六类 = Original/FS/FA/TS/TA/Mixed（四个混合类合并）。
- 来源：从 image 路径中的 `/bbc/`、`/guardian/`、`/usa_today/`、`/washington_post/` 取得。**注意：只有 orig/TS/TA 样本的路径是 `DGM4/origin/<来源>/...`；所有 FS/FA/Mixed 样本的路径是 `DGM4/manipulation/<方法>/...`，不含来源**，这些样本记为 `unknown`（test 26904 条）。因此按来源分层只覆盖 orig/TS/TA，而且各来源的类别构成不同。
- 人脸尺寸：metadata 中 mtcnn_boxes 最大框的 sqrt(w·h)，分桶 <32 / 32-64 / 64-128 / 128-256 / ≥256。

### 数据划分（先写死，后看结果）
- val 按 fake_cls 分层，`np.random.RandomState(2026)`，每类对半分 → val_dev 11060 / val_holdout 11066。清单在 `results/split_val.json`，脚本拒绝覆盖已有清单。
- 流程：`split_val.py` → `fit_freeze.py`（只在 val_dev 上拟合，报告 val_dev/val_holdout，写入 `frozen_config.json`）→ `eval_test.py`（读取冻结配置，校验 sha256，评估 test）。
- `eval_test.py` 共运行 3 次，**冻结配置哈希都相同**（`35e700fb…`）。后两次运行只是为了补写两类遗漏的输出文件（E02 的 axes/questions json、原始四头 csv），这两类文件只是把已经算出的数字落盘，没有改动任何参数或规则。`report.py` 用同一份冻结配置重新生成 val_dev/val_holdout 的报告，不做任何拟合。

### E01 解码器（规则写死在 `scripts/common.py`、`scripts/pipeline.py`）
| 名称 | 规则 | 参数（val_dev 拟合） |
|---|---|---|
| R0 / R1 | 只用二分类头，阈值 0.5 / 0.736491 | — |
| A_untuned | Binary-first：p_fake<t_b → orig；否则每一侧 max≥t_m 时取较大者，否则为"无"；两侧都"无"时取四维 argmax 作 fallback，只设置它所属的那一侧 | t_b=0.5, t_m=0.5 |
| A_tuned | 同上，网格 t_b,t_m ∈ [0.02,0.98] 步长 0.01，目标为六类 Macro-F1，并列时取离 (0.5,0.5) 最近的 | **t_b=0.86, t_m=0.71** |
| A_matchB | t_m 同 A_tuned；t_b 步长 0.001，使 val_dev Original Recall 最接近 B_tuned | t_b=0.89 |
| B_b0 | 四头联合打分：s_img(无/FS/FA)、s_txt(无/TS/TA) 为 log p / log(1-p) 之和，九类得分 = s_img + s_txt，orig 另加 b_orig；clip [1e-6, 1-1e-6] | b_orig=0 |
| B_tuned | 同上，b_orig ∈ [-10,20] 步长 0.05，目标为六类 Macro-F1 | **b_orig=0.85** |
| B_matchA | b_orig 使 val_dev Original Recall 最接近 A_tuned | b_orig=0.70 |
| B_TS_b0 / B_TS_tuned | 四维分别做温度缩放后再用 B（E03-b） | T=3.66/3.14/4.00/3.33；b_orig=0 / 0.15 |
| C_LR | 多项逻辑回归（E03-a）：特征为 logit(p_fake) 与四维 logit（用 val_dev 均值/方差标准化），九类，L2，C=1.0 | 见 frozen_config.json |

- 公平性：A_matchB 和 B_matchA 是在相近 Original Recall 工作点上的对照组；另外还有 b_orig / t_b 扫描曲线（`E01_*_orig_bias_sweep.{csv,png}`）。
- Paired bootstrap：1000 次，seed=2026，用 multinomial 重采样权重，所有解码器共用同一组权重。
- 指标口径：Original FPR = Original 被判成任意篡改类的比例；`ml_*`（FS/FA/TS/TA 的 Recall/F1、Exact Match）由解码后的九类反推出四维标签再计算；原始四个头在阈值 0.5 下的 F1/Exact Match 单独见 `E01_*_raw_heads_thr0.5.csv`。

### E02 / E03
- E02 在 A_tuned 和 B_tuned 上各做一遍，覆盖 val_holdout 和 test。错误分层按九类粒度：a 真伪（orig ↔ 非 orig）> b 模态（模态集合不同）> c 子类型（模态相同、子类型不同）；同时给出其中在六类粒度下仍然算错的数量（Mixed 内部互换在六类下不算错）。
- E03 冲突：以 p_fake≥0.5 作为"Binary 判假"。冲突组与非冲突组的错误率用三种口径对比：二分类@0.5、A_tuned 六类/九类、B_tuned 六类/九类。

### E02 补充：图像轴 / 文本轴拆分（只读 `E01_*_preds9.csv.gz`，纯 CPU）

> 追加时间：2026-10-25（阶段A结束后）。不改动任何已冻结的规则，不拟合任何参数；脚本 `scripts/axis_independence.py` → `results/E02/E02_axis_independence.csv`、`E02_axis_error_composition.csv`。bootstrap 1000 次，seed=2026。结论以 val_holdout 为准，test 仅作报告。

**目的**：九类 = 图像状态{无,FS,FA} × 文本状态{无,TS,TA}。把九类预测拆回两条轴，回答两个描述性问题：
1. Mixed 样本中，一条轴判对与否，是否与另一条轴相关？（联合判对比例 ÷ 两个单轴判对比例之积；以及 Mixed 内单轴召回 vs 对应单类样本）
2. 每条轴的错误由误报、漏检、类型混淆各占多少？

**事先预测（待验证）**：若图文之间存在可被模型利用的一致性信号，Mixed 内的联合判对会高于两个单轴之积，或单轴召回会高于单类样本。

#### 判断
- 联合 ÷ 之积 ≈ 1（val_holdout CI 含 1；test 上 A 含 1，B 略高于 1 约 0.8%）→ **解码后的两条轴的判对结果近似统计独立：支持**。未观察到"一条轴的篡改帮助另一条轴被检出"。
- 单轴召回在 Mixed 与对应单类样本之间，多数格子的差值 CI 含 0。少数格子 CI 不含 0（val_holdout：FA&TA 文本轴，B_tuned 的 FS&TA 图像轴；test：FS&TS 图像轴、FA&TA 图像轴），方向均为 Mixed 更高，但同一格子在两个 split 上不一致，且共 32 次比较（4 混合类 × 2 轴 × 2 解码器 × 2 split），不做多重比较校正：**证据不足，不据此下结论**。
- 因此 Mixed 被折叠成单模态（A 32.2% / B 29.0%）主要对应两条轴各自的召回（约 0.81 × 0.73），**未发现需要用融合失败来解释的额外损失**：证据不足以认定融合是瓶颈。
- 图像轴：误报与漏检并重，另有 FA→FS 等类型混淆；文本轴：以漏检为主（约 25–27%），类型混淆可忽略。

#### 局限（不得越过）
- 这是对**解码后输出**的描述，不是对模型内部是否使用跨模态特征的检验；不能写成"模型没有跨模态推理"。
- 单 checkpoint、单 seed；test 此前已被多次查看，仅作报告。
- 未区分原因（图像质量、来源、阈值、文本头偏保守等），原因需要 B 阶段分析。
- 四个混合类样本量差异大（FA&TA 在 val_holdout 仅 244），单类 CI 较宽。

**下一步**：图像轴误报与漏检、文本轴漏检分别进入 B 阶段；是否需要"先独立再组合"，取决于两条轴各自的最小改动原型（E08/E09）是否有净收益。

数据层面的描述（不推断原因）：
- 9 个解码器在 test 上的六类 Macro-F1 落在 0.7059–0.7114 之间，最大差 0.55 pt；在 val_holdout 上落在 0.6921–0.6973 之间。
- 在 b_orig 扫描中，Original Recall 落在 0.67–0.86 区间时，Macro-F1 的变化不超过 1.2 pt；Original Recall 与各篡改类 Recall 此消彼长。
- 全体样本上'两轴都对 ÷ 两轴准确率之积' ≈ 1.003，仅作提示；更直接的检验见'E02 补充'（Mixed 内、同一解码器），该检验显示解码后两条轴的判对近似独立，但**不据此对融合缺陷下结论**。
- 多数 Original 误报的 p_fake 和四维概率都很高，而且方向一致；两头冲突在 test 中只占 1.4%（695 条）。
